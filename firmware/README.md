# SPD programmer firmware (RP2040 Pico)

C firmware on the Pico SDK. It exposes a line-based command interface over USB
CDC; the Python tool in `../host` is the normal way to use it, but any serial
terminal works too (type `help`).

## Build

Needs CMake ≥ 3.13, `arm-none-eabi-gcc` and the Pico SDK 2.x. If
`PICO_SDK_PATH` is not set, CMake fetches SDK 2.1.1 from GitHub.

Use Arm's GNU toolchain (`arm-none-eabi`, or `PICO_TOOLCHAIN_PATH=<dir>`).
Other ARM GCCs, such as the one bundled with Xilinx Vitis, have no ARMv6-M
newlib: they link ARM-mode `strcmp` etc., and the Pico hard-faults (watchdog
reset, USB drops) on the first command.

```sh
cmake -S firmware -B build/firmware -DPICO_SDK_PATH=/path/to/pico-sdk
cmake --build build/firmware -j
# -> build/firmware/spd_programmer.uf2
```

## Flash

First time: hold BOOTSEL while plugging in the Pico and copy the `.uf2` onto
the RPI-RP2 drive, or use `picotool load -x spd_programmer.uf2`.

After that the firmware supports picotool's reset interface, so no button is
needed:

```sh
picotool load -f -x spd_programmer.uf2   # reboot into BOOTSEL, flash, run
picotool info -a -f                       # version, pin map
```

`spdtool bootsel` (or the `bootsel` command) also reboots into BOOTSEL mode.

## Safety behaviour

- Rails are only on during a command or an open session (`power on`). A
  session is closed after an idle timeout (default 10 s, `timeout <s>`), when
  the serial port is closed, on a rail over-current fault, or when a mode
  switch moves.
- Before any rail is enabled: the mode switches must be in a valid position
  and contact 8 must read as VSS (seating check). After power-up the SPD type
  bytes must match the switches (`power on force` skips only this last check,
  for repairing a corrupted SPD).
- `debug [hv]` turns the rails of the selected mode on with an **empty**
  socket, for measuring them; it switches off as soon as contact 8 stops
  reading open, and after 5 minutes without a command (1 minute with VHV;
  `spdtool debug` keeps it alive by polling). VHV is refused outside DDR4 mode.
- Any I2C transfer stops with `ERR FAULT` as soon as a rail reports an
  over-current fault.
- A 3 s hardware watchdog: a hung firmware resets, and reset returns every
  rail to its hardware default (off).

## Buttons

Program (hold 1 s) applies the active preset, Restore (short press) undoes
it; both ignored while a session or debug mode is open. Done lights on
success; on failure Fault stays lit and goes dark N times every few seconds
(1 insertion, 2 electrical, 3 wrong type, 4 refused, 5 write) until the next
press or command. Details:
`button`, and a `# button ...` notice to a connected host. Records, the
marked serial, the preset format and the flash layout:
[`../docs/program-restore.md`](../docs/program-restore.md); source structure:
[`../docs/firmware.md`](../docs/firmware.md). The built-in presets
(`src/default_presets.h`) are generated by `python -m spdtool.preset
--c-defaults` in `../host`.

## Protocol

One command per line; every command ends with exactly one `OK ...` or
`ERR <name> <message>` line (blank lines are ignored and get no reply). Lines starting with `#` are notices (help text,
automatic power-off) and can appear between commands. Numbers accept decimal
or `0x` hex; data is plain hex.

| Command | Reply |
|---|---|
| `version` | `OK fw=<x.y.z> proto=<n>` |
| `status` | `OK state=off\|on\|debug mode=... seat_mv=... vddspd_mv=... ...` |
| `power on [force]` / `power off` | `OK mode=... key=<bytes 0-3> size=... blocks=...` |
| `debug [hv]` | status line |
| `timeout <s>` | `OK timeout_s=<s>` |
| `leds` | `OK` after ~4 s: Done, Modified, Busy, Fault in turn, then all on, then the previous state |
| `leds on` / `leds off` | `OK` (all four held on/off, to compare brightness) |
| `led <done\|mod\|busy\|fault> [level]` | `OK <name>=<level>` (PWM brightness 0–1000, until reset; defaults in `board.h`) |
| `ident` | as `power on` |
| `read <addr> <len>` | `OK <hex>` |
| `write <addr> <hex>` | `OK written=<n>` (raw, verified; no CRC update) |
| `crc [fix]` | `OK <section>=<stored>/<computed> ...` |
| `wp` | `OK mask=0x.... blocks=<n> override=<0\|1>` |
| `unlock` | `OK prev=0x....` (DDR4: CWP with VHV; DDR5: clear MR12/MR13) |
| `lock [mask]` | `OK mask=0x....` (no mask: re-lock what `unlock` cleared, only on the same module) |
| `temp` | `OK milli_c=<n>` |
| `scan` | `OK <addr> ...` (7-bit hex addresses that ACK a read) |
| `mr <reg> <len>` / `mr <reg> = <val>` | DDR5 hub registers (MR11 is reserved for the firmware) |
| `program [<preset hex>]` | `OK preset=... id=... changed=<n> record=module+flash\|flash serial=...` (or `OK already applied`) |
| `restore [force]` | `OK restored=<n> record=... serial=...` (`force`: also when the contents changed since Program) |
| `record` | `OK modified=<0\|1> hash=ok\|changed\|- record=none\|module\|flash\|module+flash area=free\|record\|profiles\|used flash_records=<n> [preset=... rec=<hex>]` |
| `preset [list]` | `OK count=<n> active=<name> source=builtin\|flash names=<a,b,...>` |
| `preset get\|del\|use <name>` / `preset add <hex>` / `preset reset` | `OK name=... hex=...` / `OK` |
| `button` | `OK action=none\|program\|restore result=<OK\|error> code=<0-5> msg=<rest of line>` |
| `bootsel` / `reboot` | `OK`, then the Pico resets |

Error names: `ARGS CMD SWITCH SEAT VDDSPD FAULT NOACK IDENT WP VERIFY STATE
TIMEOUT OVERRIDE REFUSED FLASH`.

`program`, `restore` and the record format are described in
[`../docs/program-restore.md`](../docs/program-restore.md).
