# Firmware internals

Structure and behaviour of the Pico firmware (`firmware/src`). Building,
flashing and the command protocol are in
[`firmware/README.md`](../firmware/README.md); the hardware it drives in
[`hardware.md`](hardware.md); Program/Restore and its formats in
[`program-restore.md`](program-restore.md).

## Source files

| File | Role |
|---|---|
| `main.c` | Main loop: reads command lines from USB CDC, runs the buttons, the power safety checks and the idle timeouts; feeds the 3 s watchdog |
| `cmd.c` | The line protocol: parses commands, replies `OK …` / `ERR <name> …` |
| `board.c/h` | Pin map, timing constants, GPIO safe state, LEDs (PWM), ADC |
| `power.c/h` | Mode switches, seating check, rail sequencing, debug mode, VHV, the periodic safety checks |
| `bus.c/h` | I2C: attaches I2C0 (DDR5) or I2C1 (DDR4) to the right pins, transfers with timeouts, aborts on a rail fault |
| `ee1004.c/h` | DDR4 SPD (EE1004) and temperature sensor: page select, 16-byte page writes, write-protect commands |
| `spd5118.c/h` | DDR5 hub (SPD5118): registers, NVM pages, writes, write protection, temperature |
| `spd.c/h` | Generation-independent SPD access (dispatch, write + verify, CRC-16, layout) and the type check |
| `edit.c/h` | Program / Restore: preset ops, marked serial, backup records |
| `timing.c/h` | Timing-field encodings (pure C, also compiled by the host tests) |
| `store.c/h` | Flash: backup record slots and the preset sector |
| `presets.c/h` | The presets: stored set or built-in defaults, active preset |
| `default_presets.h` | Built-in presets, generated by `python -m spdtool.preset --c-defaults` |
| `ui.c/h` | Program/Restore buttons, Fault blink codes |
| `err.h` | Error codes (`ERR <name>` on the protocol) |

## Main loop and safety

Everything runs in one loop on core 0; there are no interrupts of its own and
no RTOS. Each iteration: feed the watchdog, read at most one character of a
command line (1 ms timeout), poll the buttons, run the power safety checks,
then the timeouts.

Rails are on in two states only:

- **Session** (`PWR_ON`): during a module command, or between `power on` and
  `power off`. A one-shot command (e.g. `read`) powers up, runs and powers
  down; inside an open session it just runs.
- **Debug** (`PWR_DEBUG`): `debug [hv]`, with an empty socket, for measuring.

While powered, `power_poll()` switches everything off on: a TPS2553 fault
(GP2 low), a mode switch moving, or (debug mode only) the seating check
reading anything but an empty socket (every 250 ms). The main loop adds: idle
timeout (session: 10 s by default, `timeout <s>`; debug: 5 min, with VHV 1 min),
and the USB serial port closing (DTR low). A hung firmware is reset by the
watchdog after 3 s, and reset returns every rail to its hardware default (off).

**Power-up** (`power_on`): mode switches valid (each exactly one line low) →
seating check < 200 mV → wait until ≥ 500 ms since the last power-down → Busy
LED on → rails:

- DDR4: release HSA (contact 148 becomes SCL), VDDSPD on, 5 ms, check contact 5
  ≥ 2.25 V (`ERR VDDSPD`), pull-ups on, attach I2C1.
- DDR5: HSA grounded, VIN_BULK (UDIMM) or VIN_MGMT (RDIMM) on, 50 ms for the
  PMIC LDO and the hub's power-on reset, check the fault line, pull-ups on,
  attach I2C0.

Then the type check (unless `power on force`): SPD byte 2 must be DDR4
(0x0C/0x0E) or DDR5 (0x12) as switched, byte 3 a UDIMM (DDR5: also CUDIMM) or
RDIMM type (RDIMM, LRDIMM; DDR5: also MRDIMM). Any failure powers down.

**Power-down** (`power_off`): VHV off, pull-ups off, I2C detached, rails off,
HSA grounded (also drains contact 5 and the pull-up rail), discharge wait, Busy
LED off.

**Debug mode** (`power_debug`) requires an empty socket (> 2.5 V on contact 8)
and allows VHV only in DDR4 mode.

## DDR4 (EE1004 + TSE2004)

- 512 bytes in two 256-byte pages; page select by a write to 0x36 / 0x37 (SPA0 /
  SPA1). Some devices switch without acknowledging, so the firmware confirms the
  page by probing 0x36 (ACK = page 0), like Linux's `ee1004` driver.
- Writes in 16-byte pages; completion by ACK polling (≤ 20 ms).
- Write protection: four 128-byte blocks. RPSn (read 0x31, 0x34, 0x35, 0x30 for
  blocks 0–3; ACK = not protected), SWPn (write the same addresses), CWP (0x33,
  clears all). SWPn and CWP need VHV on SA0: `hv_enable()` (DDR4 mode only,
  50 ms settle), command, `hv_disable()` (100 ms before normal access).
- Temperature sensor at 0x18, register 5.

## DDR5 (SPD5118 hub)

- Legacy 1-byte addressing: register MRn at address n (0x00–0x7F); NVM at
  0x80 + offset within the 128-byte page selected by MR11[2:0].
- **Select page 0 before any register access.** On the tested hub (a
  Renesas/IDT part on an SK hynix RDIMM), every register except MR11 reads as 0
  while another NVM page is selected: the write-protect mask, and MR48's
  write-in-progress bit too. Without this, a write after a full read skipped the
  unlock and overran the hub's write cycle (NACK). `page0()` in `spd5118.c`.
- Writes in 16-byte chunks; completion by polling MR48 bit 3 (≤ 50 ms). The hub
  may NACK a read while busy; reads retry.
- Write protection: MR12/MR13, one bit per 64-byte block. Clearing bits needs
  the offline mode (MR48 bit 2 set; HSA grounded at power-up). Writes to
  protected blocks are silently ignored, so every write is verified by reading
  back (`spd_write`), and a mismatch inside a protected block is reported as
  `ERR WP`.
- MR11 is reserved for the firmware (`mr 11 = …` is refused).

## Protocol and errors

One command per line, exactly one final `OK …` / `ERR <name> <message>` line,
`#` lines for notices (`firmware/README.md` has the full table). Error names:

| Name | Meaning |
|---|---|
| `ARGS`, `CMD` | bad arguments, unknown command |
| `SWITCH` | mode switches between positions |
| `SEAT` | seating check failed (or not empty, for debug mode) |
| `VDDSPD` | DDR4 contact 5 below 2.25 V |
| `FAULT` | TPS2553 over-current |
| `NOACK`, `TIMEOUT` | I2C: no acknowledge; a line held low |
| `IDENT` | SPD type does not match the switches |
| `WP` | write blocked by write protection |
| `VERIFY` | read-back differs |
| `STATE` | not allowed now (e.g. in debug mode) |
| `OVERRIDE` | DDR5 offline mode not active |
| `REFUSED` | Program/Restore refused (message says why) |
| `FLASH` | flash write failed or preset storage full |

Every error lights Fault (steady) and clears Done; the next command clears
Fault.

## Extending

**A new preset op:** add the op number and its encoding to the table in
`edit.h`, handle it in `run_ops()` in `edit.c` (parse with the `get8/get16/
get32/take` cursor helpers; apply only when `apply` is true, so validation can
walk the preset without a module; refuse with `E_REFUSED` and a message when it
does not apply), add an `Op` helper and a decoder branch in
`host/spdtool/preset.py`, and document it in `program-restore.md` and
`host/README.md`. Ops must not write the serial, CRC bytes or record area
(`check_off()`).

**Changing the built-in presets:** edit `DEFAULTS` / `DEFAULT_ACTIVE` in
`host/spdtool/preset.py`, regenerate `default_presets.h`, rebuild.
`host/tests/test_preset.py` fails if the header is out of date. Boards that
already have presets stored keep theirs until `spdtool preset reset`.

**Timing fields:** `timing.c` must stay identical in behaviour to the host's
field encoders; `host/tests/test_firmware_timing.py` compiles it and compares
every field.

## Debugging

- `help` over a serial terminal lists the commands; `spdtool -v <command>`
  shows the protocol.
- `picotool info -a -f` shows the firmware version and pin map (binary info).
- `record`, `button`, `preset list` show the Program/Restore state.
- If the board drops off USB on the first command, check the toolchain
  (`firmware/README.md`): a GCC without an ARMv6-M newlib links ARM-mode C
  library code that hard-faults the Cortex-M0+.
